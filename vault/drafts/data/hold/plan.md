# Расширенный датасет Binance USDⓈ-M (USDT-перпы) — план сборки (записан ДО загрузки)

Записан 2026-10-16 ~10:50 UTC, после коротких проб API (probe.py, probe2.py: 2 вызова exchangeInfo/time,
8 коротких klines, 3 fundingRate, 1 fundingInfo, 2 листинга имён), до запуска основной загрузки и до
просмотра любых сводных чисел. Отступления от плана будут отдельно помечены в results.md.

## Цель

Не 10 монет, а весь универсум USDT-перпов Binance с историей ≥ 1 года, включая делистнутые, для будущих
исследований «куда пойдёт цена / сколько держать» (hold-исследование). Это только датасет + индекс,
без торговых выводов.

## Источники (жёстко)

- Свечи: только `https://fapi.binance.com/fapi/v1/klines` без ключей, `limit=1500`, `startTime=1`,
  `endTime=now_ms-1`, постранично. Только закрытые бары (`close_time < now_ms`). `now_ms` фиксируется один
  раз в `cache/meta.json` (как в gaps_study.py), чтобы докачка была воспроизводимой.
- Фандинг: `/fapi/v1/fundingRate` (`startTime=1`, `limit=1000`, постранично; `startTime=0` API игнорирует —
  проверено) и `/fapi/v1/fundingInfo` (интервалы 4ч/1ч у части символов; по умолчанию 8ч).
- Список символов: `/fapi/v1/exchangeInfo` (снимок сохранён в `exchangeInfo.json`): `quoteAsset=USDT`,
  `contractType=PERPETUAL`. Статусы: TRADING (живые), SETTLING (делистнутые, цена заморожена),
  PENDING_TRADING (ещё не торгуется). `TRADIFI_PERPETUAL` (токенизированные акции/металлы, 2026 г.)
  исключаются — другой рынок, истории < 1 года.
- Дополнение к ошибке выжившего: публичный листинг имён в бакете Binance `data.binance.vision`
  (`data/futures/um/monthly/klines/`, только имена папок, без скачивания данных оттуда) дал 32 USDT-перпа,
  которых exchangeInfo уже не отдаёт (MATICUSDT, LUNAUSDT, SRMUSDT, BTSUSDT, ...). Для них история берётся
  тем же `/fapi/v1/klines` (проверено: отдаёт). Остаток ошибки выжившего = символы, которых нет ни там,
  ни там; оценить его нельзя — записать как ограничение.
- Не трогаются: 127.0.0.1:8321, BingX (бан 109429), запись в OSKAR. Интерпретатор — OSKAR/.venv (pandas,
  httpx; pyarrow нет → формат csv.gz, а не parquet).

## Темп запросов

- klines: вес 10 за запрос при limit=1500, лимит 2400 веса/мин → не более 240 запр/мин. Цель ≈ 3 запр/с
  (пауза ≥ 0.33 с), контроль заголовка `x-mbx-used-weight-1m`: > 2000 → пауза 25 с.
- fundingRate: отдельный лимит 500 запросов / 5 мин → ≈ 1.4 запр/с (пауза 0.72 с) в отдельном процессе.
- Суммарно ≤ 4.5 запр/с < 5. 429 → пауза 60–120 с и повтор; 418 (бан) → немедленная остановка с логом.
- Оценка объёма: ~690 кандидатов × 1d (~1000 запр.) + ~550 × 4h (~3300) + 50 × 1h (~1500) + фандинг
  (~2200). Ожидаемое время 35–45 мин двумя параллельными процессами.

## Порядок (все файлы — только в drafts/hold/)

1. **Фаза A** — 1d для всех кандидатов (658 + 32). По 1d определяется реальная история.
2. **Фильтр универсума**: история ≥ 365 дней = (last_real_open − first_real_open) ≥ 365·86400000 мс.
   «Реальный» бар — после обрезки хвоста призрачных баров (см. ниже).
3. **Фаза B** — 4h, вся история, для универсума.
4. **Фаза C** — топ-50 по сумме `quote_volume` (USDT) 1d-баров за последние 365 дней среди живых символов
   универсума → 1h, вся история.
5. **Фандинг** (параллельный процесс) — для всех кандидатов, весь период.
6. **Индекс**: 1w агрегируется из 1d (неделя с понедельника 00:00 UTC: week_start = ⌊(t − 4д)/7д⌋·7д + 4д,
   эпоха 1970-01-01 — четверг); open=первый, high=max, low=min, close=последний, объёмы — суммы, `n_days` —
   число дней в неделе (7 = полная; неполные первая/последняя остаются в файле с n_days < 7).
   `universe.csv`: symbol, source, status, underlying, onboard_date, first_bar, last_bar, delisted,
   delist_date, history_days, n_1d, n_4h, n_1w (полных), n_1h, n_funding, funding_interval_h,
   qv_365d_usdt, rank_365d, top50_1h, missing_4h, ghost_inner_1d, ghost_trimmed_1d.
   `candidates_all.csv` — все кандидаты с причиной исключения.

## Призрачные бары (делистинг)

После делистинга Binance продолжает отдавать плоские бары (O=H=L=C, volume=0) месяцами/годами
(SRMUSDT: 560 таких 1d-баров; SCUSDT: > 1000). Правило: **хвостовой** непрерывный ряд баров с volume=0
обрезается на каждом ТФ отдельно; число отрезанных пишется в лог. Нулевые бары **внутри** ряда (пауза
торгов, перелистинг, неликвид) не трогаются, только считаются (`ghost_inner_1d`).
Делистнутый = статус SETTLING, или символа нет в exchangeInfo (REMOVED), или последний реальный 1d-бар
старше now − 3 дня. `delist_date` = последний реальный 1d-бар + 1 день.

## Формат файлов (совместим со старыми кешами: первые 7 колонок те же)

`cache/{SYMBOL}_{1h|4h|1d|1w}.csv.gz`: open_time, open, high, low, close, volume, close_time,
quote_volume, trades, taker_buy_volume, taker_buy_quote_volume (+ n_days для 1w). Время — мс UTC.
`cache/{SYMBOL}_funding.csv.gz`: funding_time, funding_rate, mark_price.
`cache/meta.json` — now_ms снимка. `fetch_log_*.jsonl` — по файлу: сырых баров, сохранено, обрезано, запросов, секунд.

## Издержки для будущих расчётов (как OSKAR risk/sizing.py)

Taker 0.05% от notional на каждую ногу (TAKER_FEE_PCT), проскальзывание стоп-аута 0.05% (STOP_SLIPPAGE_PCT),
1R = ход до стопа + проскальзывание + комиссии обеих ног (stop_loss_per_unit). Фандинг — отдельно: на каждом
`funding_time` внутри удержания начисляется rate × notional со знаком (лонг платит при rate > 0); интервал —
из fundingInfo (по умолчанию 8ч). В sizing.py фандинг не учитывается — здесь он нужен именно потому,
что исследуется долгое удержание.

## Критерии успеха (объявлены до расчёта)

1. Универсум ≥ 400 символов с историей ≥ 1 года; доля делистнутых указана с разбивкой SETTLING / REMOVED.
2. У каждого символа универсума есть файлы 1d и 4h; доля пропущенных 4h-баров внутри диапазона
   (ожидаемо − фактически) ≤ 0.5% у ≥ 95% символов; остальные перечислены.
3. Сверка с прежними кешами на пересечении для 10 монет: 1d против gaps/cache 1d и 4h против
   candles/cache 4h — close совпадает (отн. расхождение ≤ 1e-9) на ≥ 99.9% общих баров.
4. Сверка агрегата 1w с «родным» 1w Binance (gaps/cache, BTC/ETH) на полных неделях: OHLC совпадают
   (отн. ≤ 1e-9). Несовпадение = ошибка границы недели → чинить, не публиковать.
5. Ни одного 418; число 429 записано; заголовок used-weight-1m никогда не превышал 2400.
6. Отчёт results.md по-русски: размер универсума, доля делистнутых, диапазон дат, число баров по ТФ,
   время загрузки, проблемы и честные ограничения (ошибка выжившего, переименования MATIC→POL и т.п.
   не склеиваются, 1h только у топ-50 → смещение к крупным монетам, объём в USDT, не в монетах).

# Часть 2 — hold-исследование «куда пойдёт цена» (план записан ДО расчёта)

Записан 2026-10-16 ~12:20 UTC, до написания расчётного кода hold_study.py и до просмотра любых чисел.
Отступления от плана помечаются в results.md отдельно.

## Тезис Ивана и что измеряется

Незакрытый FVG-гэп старшего ТФ (1d, 1w) — цель; вход после признака разворота в его сторону; суть — ДОДЕРЖАТЬ
до прихода цены в зону, не уйдя в ликвидацию. Ночной setup_study измерял «как пойдёт» (стоп + тайм-аут 48 баров).
Здесь измеряется напрямую «куда»: доля событий, после которых цена дошла до гэпа, за какое время и какой ценой
(максимальная просадка против входа до прихода, фандинг). Без стопа, без тайм-аута 48 баров.

## Данные

- Binance USDⓈ-M, публичные закрытые свечи 4h из `drafts/candles/cache` (вся история контракта):
  BTC ETH SOL XRP DOGE BNB ADA AVAX LINK SUI (BTC с 2019-09, SUI с 2023-05). 1d и 1w — агрегация 4h
  (UTC; неделя с понедельника 00:00), как в setup_study.py; первый неполный и последний незакрытый HTF-бар отброшены.
  Сверка агрегата 1w с «родным» 1w из gaps/cache (BTC, полные недели) — в results.md.
- Расширенный универсум (hold/cache, build_dataset.py) на момент записи содержит только 1d для ~340 символов,
  4h ещё нет (фаза B не началась; оба процесса загрузки с 12:11 UTC не пишут в лог). Скрипт принимает
  `--universe hold` и подхватит `{SYM}_4h.csv.gz`, когда они появятся. Делистнутых среди 10 монет нет →
  разрез «с делистнутыми / без» сейчас недоступен и отмечен как ограничение.
- Фандинг: `/fapi/v1/fundingRate` по каждому из 10 символов, кеш `hold/cache/{SYM}_funding.csv.gz` в формате
  build_dataset.py (builder пропускает существующие файлы). Темп ≤ 0.7 запроса/с, 429 → пауза 65 с.
  Для символов без файла фандинга — средний по датасету ряд (среднее ставок доступных символов по времени).
- Не трогаются: 127.0.0.1:8321, BingX, запись в OSKAR. Интерпретатор — OSKAR/.venv (numpy, pandas, httpx).

## Определения (все известно на закрытии бара; копия функций setup_study.py)

- **ATR** — Wilder ATR(14) 4h на сигнальном баре; расстояния измеряются в этих ATR и в % от цены входа.
- **FVG** (как gaps_study/setup_study): HTF-бар i — третья свеча; бычий: low[i] > high[i−2], зона [high[i−2]; low[i]]
  (под ценой → цель SHORT); медвежий: high[i] < low[i−2], зона [high[i]; low[i−2]] (над ценой → цель LONG);
  фильтр микрогэпов ≥ 0.1 ATR(14) HTF. Гэп известен с закрытия бара i.
- **Жизнь гэпа**: жив, пока цена не прошла дальнюю границу (по high/low 4h, включая сигнальный бар); частичное
  заполнение сдвигает ближнюю границу. near — ближняя граница оставшейся части, far — дальняя, CE = (near+far)/2.
- **Гэп-цель** на баре t: ближайший живой гэп 1d/1w в сторону d с (near − close)/ATR ∈ [1.5; 8]. Цели near/CE/far
  фиксируются на момент сигнала и дальше не сдвигаются.
- **Сигналы 4h** (LONG; SHORT зеркально), ровно как в setup_study.py:
  (b) CHoCH по закрытию: фракталы k=2, на t−1 структура медвежья (LH и LL), close[t] > последний свинг-хай ≥ close[t−1],
  один сигнал на свинг-хай; (d) = (b) при условии, что между пробитым свинг-хаем и t был доджи у 20-барного минимума
  (тело ≤ 10% диапазона, low ≤ min 20 предыдущих, не новый максимум, ход от 20-барного максимума ≥ 1.5 ATR).
- **Вход** = close сигнального бара t. **Без стопа и тайм-аута**: горизонт HMAX = 90 дней = 540 баров 4h; событие
  учитывается, только если после него есть полные 540 баров (последние 90 дней истории исключены). Прогрев 40 баров.
- **Достижение цели**: первый бар t+k (k = 1..540), где high ≥ цели (LONG) / low ≤ цели (SHORT). Время = k/6 дней.
- **MAE** до цели: для достигших — entry − min(low[t+1..t+k]) (LONG; включая бар касания — консервативно), в ATR и в %
  от entry; для недостигших — MAE за все 540 баров (отдельная строка). Квантили P50/P80/P95.
- **Плечо выживания**: изолированная маржа, ликвидация при ходе против ≈ (1/L − 0.5%) от цены → L_max = 1/(MAE% + 0.5%),
  грубо, без комиссий, фандинга и тир-ставок поддержки (у альтов MMR выше → L_max меньше). Считается для P50/P80/P95 MAE.
- **R при стопе на P95 MAE**: стоп = entry − d·P95(MAE_ATR достигших CE в этой ячейке)·ATR; цель near или CE; без
  тайм-аута до 540 баров (неисход → выход по close t+540); стоп и цель в одном баре = стоп; открытие за стопом = по open.
  Издержки как OSKAR risk/sizing.py: taker 0.05% каждая нога, проскальзывание стопа 0.05%; 1R = ход до стопа +
  проскальзывание + комиссии обеих ног. P95 берётся по той же выборке (in-sample) — помечено как оптимистичное.
- **Фандинг**: Σ ставок с funding_time ∈ (close_time[t]; close_time[t+k]] со знаком против позиции (LONG платит при
  rate > 0), в % от notional; для достигших — до касания, для всех — за фиксированные 30 дней. Отдельно от комиссий.
- **Тренд 1d**: close последнего закрытого 1d-бара выше EMA50(1d) = аптренд. LONG в аптренде / SHORT в даунтренде = «по тренду».
- **Размер гэпа**: (far − near)/ATR(4h) на сигнальном баре; терцили по основным событиям.

## Контроли

- **K1 «сигнал без гэпа»** (главный): тот же сигнал (b)/(d), в сторону сигнала нет живого гэпа 1d/1w с near ≤ 10 ATR.
  Цели синтетические: тройка расстояний (near, CE, far в ATR) берётся целиком у случайного настоящего события той же
  ячейки (сигнал × направление), 3 розыгрыша на событие, вес каждого 1/3. Отвечает: «добавляет ли гэп к сигналу».
- **K2 «гэп без сигнала»** (описательно, не в вердикте): для каждого основного события — 1 случайный бар в окне ±100
  баров того же символа с гэп-целью того же направления в коридоре и без сигнала того же вида; цели — его собственные
  near/CE/far. Отвечает: «добавляет ли сигнал к гэпу».

## Разрезы (доля достижения CE и near за 30 и 90 дней, основные vs K1)

ТФ гэпа 1d vs 1w; направление long/short; по тренду 1d vs против; терцили размера гэпа; годы 2019–2026; BTC/ETH vs альты.
Делистнутые — недоступно (см. данные).

## Статистика

Кластерный бутстрап: кластер = ISO-неделя сигнального бара (все символы вместе), 2000 повторов, перцентильный 95% ДИ;
разности с K1 — общие веса кластеров. Проверка на наложение 90-дневных удержаний: те же ДИ с кластером 13 недель
(квартал) для главных ячеек; для вердикта — более широкий ДИ.

## Критерий «тезис “куда” подтверждён» (объявлен заранее)

Главные ячейки: HTF = {1d, 1w}, сигнал (b) и (d) отдельно, long + short вместе, цель **CE**, горизонт **30 дней** — 2 ячейки.
Ячейка подтверждает, если одновременно:
1. доля достижения CE за 30 дней − K1 ≥ **10 п.п.**, и 95% ДИ разности (недельные и квартальные кластеры) не накрывает 0;
2. разность > 0 в обеих половинах периода (по медиане времени основных событий ячейки).
Бонферрони на 2 ячейки: п.1 также на 97.5% ДИ → «подтверждено»; только на 95% → «намёк».
Разность > 0 с ДИ вне нуля, но < 10 п.п. → «слабый эффект: гэп помогает меньше, чем заявлено».
Иначе → «куда» не подтверждено (гэп как цель не лучше произвольного уровня на том же расстоянии).
Отдельно и вне вердикта — **цена удержания**: P95 MAE, плечо выживания, R при стопе на P95 MAE, фандинг; это описывает,
какой профиль позиции требует «додержать», даже если «куда» подтвердится.

## Новые разрезы и метрики
- Тренд 1w: close последнего закрытого 1w-бара > EMA20(1w) (нужно ≥ 20 полных недель, иначе n/a). «По тренду» =
  направление сделки совпадает с трендом. Разрезы: тренд 1d (EMA50, как в части 2), тренд 1w, «оба по тренду / оба против / разнобой».
- Капитализация: BTC/ETH; топ-50 по quote volume за 365 д (universe.csv `top50`, только живые); остальные (включая все делистнутые).
- Годы 2020–2026 (2019 — 3 символа, строка приводится, но не интерпретируется).
- «Додержать без ликвидации»: плечо L ∈ {1, 2, 3, 5, 10, 20}, изолированная маржа, MMR 0.5 % → ликвидация при ходе против
  ≥ 100/L − 0.5 %. Метрики: доля событий, где CE достигнут за 30/90 дней **до** ликвидации при L; доля ликвидаций за 90 дней
  при удержании до CE (достиг → MAE до касания; не достиг → MAE за 90 дней; усечённое делистнутое без касания = 100 % = ликвидация).
  `MAE удержания до CE` = MAE до касания у достигших, MAE90 у недостигших — квантили P50/P80/P95 и плечо 1/(P95 + 0.5 %).
  Плечо «додержать в 95 %» по достигшим CE (часть 2) — остаётся.
- Пул K1 (тройки расстояний near/CE/far в ATR 4h) — общий по всем символам ячейки sig × d (как в части 2: «той же ячейки»).
- Все остальные определения (гэп, сигналы, цели, K2, бутстреп, половины периода) — без изменений из части 2.

## Критерий вердикта
Без изменений (часть 2): ячейки (b) и (d), цель CE, 30 дней, main − K1 ≥ 10 п.п., 95 % ДИ (недельные и квартальные кластеры)
вне нуля, разность > 0 в обеих половинах периода; Бонферрони на 2 ячейки (97.5 % ДИ) → «подтверждено», только 95 % → «намёк».
Население для вердикта — «с делистнутыми». Вариант «без делистнутых» приводится рядом и в вердикте не участвует.
