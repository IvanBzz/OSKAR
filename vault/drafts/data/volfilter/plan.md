# План: фильтр по волатильности на counterfactuals OSKAR (пред-регистрация)

Записано 2026-10-16 03:23 UTC, ДО расчёта любых исходов в разрезе ATR%.
Что я видел до записи плана: схему БД, один пример candidate_json, код резолвера
(`core/cycle.py:230-289`, горизонт 48 баров 15м = 12 ч), модель издержек (`risk/sizing.py`),
структурные счётчики журнала (без связи с ATR): 290 строк, 270 с исходом, 20 висят (созданы
16.10 после 00:00, горизонт ещё не прошёл), 57 дорешены позже суток (33 из них — сетапы 30–31.08),
входы: 221 market, 69 лимитных. Данные только за 8 дней: 30.08 (58), 31.08 (4), 11.10 (15),
12.10 (5), 13.10 (5), 14.10 (129), 15.10 (44), 16.10 (30). Источник гипотезы — предварительный
взгляд прошлого агента на ВСЮ выборку (низкая ATR% +0.92R, высокая −0.10R, без комиссий, iid).
Поэтому временное разбиение ниже — не чистый out-of-sample: гипотеза уже видела обе половины.
Чистая проверка возможна только на данных после 16.10.

## Гипотеза (односторонняя)

H1: сетапы с высокой ATR% (features.atr_pct) дают меньший средний R после комиссий, чем остальные.
Фильтр-кандидат: **не брать сетап, если atr_pct > T, где T = 66.7-й перцентиль atr_pct первой
половины данных** (граница верхней терцили).

## Единица анализа и исход

- Единица — вошедшая гипотетическая сделка. Лимитный вход, не достигнутый за горизонт, — «не вошёл»
  (исключается из средних, считается отдельно).
- R = ход цены / |entry − sl| (знаменатель — валовый риск, как в журнале).
- Издержки как в `risk/sizing.py`: taker 0.05% от notional каждой ноги, на стопе ещё 0.05% от entry
  проскальзывания (выход хуже триггера). TP — по цене TP, taker. Выход по горизонту — по цене, taker,
  без проскальзывания. Фандинг не учитывается.
  - TP: R_net = (|tp−e| − 0.0005·(e+tp)) / D
  - SL: x = sl ∓ 0.0005·e; R_net = −(|e−x| + 0.0005·(e+x)) / D
  - горизонт: R_net = (dir·(p12−e) − 0.0005·(e+p12)) / D, p12 — цена через 12 ч после ts кандидата.

## Варианты данных (исходы)

- **J_all** — журнал: tp_hit/sl_hit как записано; expired_flat переоценён по Binance USDⓈ-M 1m на
  ts+12ч (уровни пересчитаны в цены BingX множителем k = цена BingX market / close Binance на
  закрытии последней 15м свечи до ts). Для лимитных expired_flat вход проверяется по Binance:
  не коснулся — «не вошёл». Нет символа на Binance или цена не сходится (>2% после k∈{1,1000,…}) —
  `no_data`, исключается.
- **J_ontime** — J_all без 57 исходов, дорешённых позже 24 ч после создания. **ОСНОВНОЙ вариант.**
- **B_all** — полное переразрешение по Binance 1m логикой текущего резолвера: бары, открывшиеся в
  (ts, ts+12ч]; лимит сначала должен быть достигнут; в одном баре SL раньше TP; нет исхода — выход по
  цене на ts+12ч. Только символы с данными Binance.
- **B_ontime** — B_all без тех же 57 (для сравнения с J_ontime).

## Тесты

Бутстреп: 10 000 повторов, seed 20261016, перцентильный 95% CI, ресэмплинг кластеров.
Основные кластеры — сутки UTC по ts (как требует задача). Из-за 8 дней (а во второй половине ≤3)
дневной бутстреп почти вырожден, поэтому параллельно считаю блоки по 4 ч UTC (больше кластеров,
но внутридневную корреляцию учитывают хуже — интервалы, вероятно, занижены).

0. **Воспроизведение** старой цифры: только журнальные TP/SL, R без комиссий, терцили, iid-бутстреп.
1. **Терцили ATR%** (границы — 33.3/66.7 перцентили atr_pct по всем 270 дорешённым строкам, единые
   для всех вариантов): N, доля TP/SL/горизонт, средний R до и после комиссий, CI (сутки), медиана
   стопа в % и в ATR, медиана издержек в R. Разница «низкая − высокая» с CI (сутки и 4 ч).
2. **Непрерывная зависимость**: МНК R_net ~ a + b·atr_pct; наклон b с CI (сутки и 4 ч).
   Чувствительность: то же с фиксированными эффектами дня (снимает «какой день — такая ATR и такой исход»).
3. **Когорты** (risk_rejected / scout_pass / shadow) и **направления** (long / short) × терцили —
   описательно (N малы, тестов нет).
4. **Временное разбиение (подтверждающий тест)**: сортировка по ts, первая половина по числу сделок —
   выбор T (P66.7 atr_pct первой половины). Вторая половина — проверка:
   Δ2 = mean R_net(atr ≤ T) − mean R_net(atr > T).
   **Критерий успеха** (решение «есть основание для фильтра»): в J_ontime Δ2 > 0 и нижняя граница
   95% CI (блоки 4 ч) > 0; знак Δ2 совпадает в J_all и B_all; дневной CI — для справки.
   Плюс показываю, насколько фильтр меняет средний R всей стратегии во второй половине
   (mean R_net(kept) − mean R_net(all)).
   Вторичное (не решающее): T выбирается по сетке перцентилей первой половины {50, 60, 66.7, 75, 80, 90}
   по максимуму среднего R_net оставленных (не меньше 20 оставленных), затем та же проверка.
5. **Чувствительность**: leave-one-day-out для разницы терцилей (держится ли вывод без одного дня).
6. **Механизм** (разведка, не тест): R до комиссий против издержек в R по терцилям, стоп в ATR.
