# Инструменты распознавания паттернов: правила, CV, LLM с картинкой

> Отчёт агента к [[2026-10-16 — распознавание свечных паттернов — правила, CV или LLM (гипотезы)]]. Ждёт разбора → [[черновики ждут разбора]].

**Коротко.** Начинать стоит с H1, своих формул по OHLC. Сначала запускать в shadow, затем пускать в гейт только узкий список паттернов, совпадающих по направлению со сделкой и стоящих у зоны. H3 (LLM по картинке) проверять офлайн как разметчик, на сделки он не влияет. H2/H5 и готовые YOLO-модели сейчас не нужны.

Ещё один вывод из кода: если сделать условием гейта «любой из 62 паттернов», гейт фактически ослабнет до «OB или FVG», и поток сделок вырастет.

Метки силы доказательств: **[лок.]** проверено локально, **[перв.]** первоисточник, **[втор.]** вторичный источник или самоотчёт, **[оц.]** моя оценка.

## 1. Правила по OHLC (H1)

**pandas-ta 0.4.71b0 [лок.]**
- В списке 62 имени паттернов, но без TA-Lib работают только `doji` и `inside`.
- На `engulfing` и `hammer` он печатает «Requires TA-Lib» и возвращает пустой результат.
- TA-Lib в `.venv` не установлен.
- Доджи в pandas-ta: тело < 10% от среднего диапазона (H−L) за 10 предыдущих баров. Это копия правила TA-Lib.

**Колёса TA-Lib для Windows сейчас есть [перв.]**
- Начиная с версии 0.6.5 (07.08.2025) готовые колёса включают C-библиотеку, компилятор не нужен.
- Последняя версия 0.8.2 от 12.10.2026, есть `cp312-win_amd64`, требует только numpy.
- Версия 0.8.x сменила часть умолчаний (BBANDS, APO/PPO) и API `stream`. Если ставить, брать проверенную версию 0.6.x/0.7.x с фиксацией версии.
- Ничего не устанавливал: скачивание требует твоего разрешения.

**Подводный камень [лок.]**
- В pandas-ta у `rsi`, `ema`, `atr` и `macd` параметр `talib` по умолчанию True.
- Значит, установка TA-Lib в venv **молча переключит** индикаторы в `indicators.py` на реализацию TA-Lib, и числа могут измениться.
- Это поведенческое изменение по ст. 5. Нужно либо явно передавать `talib=False`, либо держать TA-Lib только в тестах как эталон.

**Свой код без зависимостей (рекомендую).** Пороги взяты из таблицы TA-Lib `TA_CANDLE_DEFAULT_SETTINGS` [перв.], исходники проверены:
- длинное тело: тело больше среднего тела за 10 баров;
- тело доджи: не больше 0.1 × среднего (H−L) за 10;
- очень короткая тень: меньше 0.1 × среднего (H−L) за 10;
- длинная тень: больше тела (у Нисона для молота нижняя тень ≥ 2 тел; это книжный критерий, его надо калибровать);
- «рядом» (Near): 0.2 × среднего (H−L) за 5;
- «равно» (Equal): 0.05 × среднего (H−L) за 5.

Набор паттернов: доджи, молот/пин-бар, падающая звезда, поглощение, харами, внутренний бар, марубозу, утренняя/вечерняя звезда.

Две вещи из исходников TA-Lib [перв.]:
- `CDLHAMMER` **не проверяет тренд**. Контекст «у минимума или у зоны» OSKAR должен добавлять сам, например через OB/FVG.
- `CDLMORNINGSTAR` требует, чтобы тело второй свечи целиком было ниже тела первой (разрыв между телами). На 15м крипте 24/7 открытие почти равно предыдущему закрытию, поэтому такие паттерны почти не будут срабатывать [оц., не измерено]. Нужна ослабленная версия.

`CDLENGULFING` сравнивает только тела и возвращает ±100, а при точном касании границ ±80.

## 2. CV (H2)

- **GAF-CNN** (Chen & Tsai, Financial Innovation 2020) [перв.]
  - Окно 10 свечей, сеть крошечная (2 свёрточных слоя), GPU не нужен [оц.].
  - Точность 90.7% на EUR/USD 1м.
  - Но метки делались **правилами**, на реальных данных даже ослабленными, а тест всего 350 примеров. Сеть учится повторять правила и не может быть точнее их.
- **CNN на картинках с метками по исходам** (Jiang, Kelly, Xiu, Journal of Finance 2023) [перв., абстракт]
  - Находит предсказательные формы на дневных акциях США. Данных нужно на десятилетия и тысячи бумаг.
  - Высокие Sharpe в пересказах блогов [втор.], на крупных бумагах они резко падают.
  - Для 15м крипты не проверялось.
- **YOLO на HuggingFace** [втор., самоотчёт]
  - `foduucom/stockmarket-pattern-detection-yolov8`: 6 фигур графика (голова-плечи, M, W, треугольник), mAP@0.5 = 0.614, около 9000 скриншотов неизвестного происхождения, свечных паттернов нет.
  - Другая модель с pinbar/engulfing: mAP50 около 0.43, датасет не указан.
  - Ultralytics распространяется под AGPL-3.0 (по памяти, не проверял).
- Рендер: `mplfinance` уже стоит. `render_chart` рисует 120 свечей на ~1000 px, это около 8 px на свечу. Для паттернов нужна обрезка до 20–30 свечей.

## 3. LLM по картинке через подписку (H3)

**Как передать картинку**
- По документации Claude Code достаточно дать путь к PNG в промпте, Claude читает его инструментом Read [перв.].
- Но в OSKAR `claude_cli.py` **запрещает Read** (`DISALLOWED_TOOLS`, ревью 2026-10-13) [лок.].
- Значит, нужно точечно разрешить чтение только папки с графиками внутри `data/agent_cwd`.
- Передача картинки в stdin через `--input-format stream-json` для CLI официально не описана, есть жалоба на ошибку 400 в SDK [втор.].
- Режим `--bare` не работает с подпиской: он требует API-ключ [перв.].

**Скорость и расход**
- Текстовый Scout сейчас: медиана 48 с, p90 70 с (n=93, `analysis_log`) [лок.].
- С картинкой ожидаю тот же порядок [оц.]: картинка 1000×600 — это около 800 визуальных токенов (формула ⌈w/28⌉·⌈h/28⌉ [перв.]).
- Каждый кандидат — ещё один вызов из бюджета подписки.

**Надёжность**
- Я не нашёл ни одной рецензированной работы с точностью LLM на доджи и поглощение на реальных графиках. Работа arXiv 2607.15414 сама помечает свои данные как «simulated/illustrative».
- «VLMs are blind» (ACCV 2024) [перв.]: на простейшей геометрии в среднем 58%, лучший Sonnet-3.5 — 77.8%.
- Документация Anthropic [перв.]: пространственные выводы и подсчёт приблизительные, возможны галлюцинации.
- Бенчмарк по свечным картинкам, 2026 [перв.]: модели (Claude Sonnet 4.5, GPT-4o и др.) угадывают направление на 49–53%, это почти случайно. Но это прогноз доходности, а не распознавание паттернов.

## 4. Гибрид (H4)

H1 находит кандидатов строго и дёшево. LLM только подтверждает выбором из меню: «подтверждаю / контекст не тот / нет паттерна». Решения и числа остаются у правил.

## Порядок

1. **H1 в shadow.** Паттерн пишется в кандидата, но в гейт не идёт. Свой код; TA-Lib, если вообще ставить, — только эталоном в тестах.
2. **Замерить на истории и контрфактах**, как часто срабатывает каждый паттерн и как ведут себя когорты «с паттерном» и «без». Сырых OHLC в `oskar.db` нет [лок.], нужна выгрузка истории.
3. **Включать в гейт только узкий список**, совпадающий по направлению со сделкой и стоящий у OB/FVG. Это отдельное изменение по ст. 5, со своим инвариантом.
4. **H3 офлайн, пачкой.** На срабатываниях H1 плюс случайных барах без паттерна мерить, как часто LLM «видит» паттерн там, где его нет, и насколько совпадает с правилами. Если результат полезный, переходить к H4.
5. **H2/H5 позже**, и только для фигур графика или если H3 покажет, что важен контекст.
