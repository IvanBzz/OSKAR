# Две машины — vault в репозитории, демон только на одной

## Проблема

Разработка шла на стационарном ПК, Obsidian-vault жил там же. Иван открыл ноутбук — как продолжать.

## Решение (оно уже было заложено)

**Vault лежит ВНУТРИ git-репозитория** (`OSKAR/vault/`, 63 файла отслеживаются). Это решение принято в Фазе 0 ровно на такой случай: документация, знания, логи прогонов и changelog путешествуют вместе с кодом одним `git clone`. Никакого Syncthing/Dropbox не нужно.

Развертывание на новой машине: `scripts/bootstrap_machine.ps1` — клон + uv sync + тесты + caps-verify, печатает что осталось.

## Что НЕ в git (и не будет)

| Файл | Почему | Как переносить |
|---|---|---|
| `.env` | секреты (ключи BingX, токены ботов, OAuth Claude) | вручную, один раз |
| `data/*.db` | журнал сделок — состояние конкретного прогона | только вместе с торговлей |
| `data/knowledge.db` | производная от vault | пересобрать: `oskar knowledge index` |

## Жесткое правило: демон на ОДНОЙ машине

Урок v1 (двойная позиция ADA от двух экземпляров) уже защищен port-lock'ом, но lock локальный — на разных машинах он не поможет. Правило: **торгует та машина, где запущен `oskard`**; вторая — только разработка и чтение vault. Гарантия на уровне биржи: `clientOrderId` содержит `run_id`, и реконсиляция покажет чужие позиции как `missing_in_journal`.

## Ритм работы

Утром `git pull`, вечером `git push`. Конфликты в vault практически исключены: changelog пишется сверху, заметки атомарные.
