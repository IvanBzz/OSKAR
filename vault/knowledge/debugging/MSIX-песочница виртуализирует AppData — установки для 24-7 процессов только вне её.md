# MSIX-песочница виртуализирует AppData — установки для 24/7 процессов только вне её

## Симптом

Hermes установился в `%LOCALAPPDATA%\hermes`, но трейсбек `hermes auth` показал СМЕШАННЫЕ пути: exe в `C:\Users\Ivan\AppData\Local\hermes\bin\`, а python-модули в `C:\Users\Ivan\AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\hermes\...` — часть записей ушла в виртуализированный слой песочницы Claude Desktop (MSIX перенаправляет записи в AppData у упакованных приложений и их детей).

## Почему это опасно

Изнутри песочницы обе проекции видны и «работают» (Test-Path оба true — слитый вид). Но процесс, запущенный Иваном из СВОЕГО терминала (вне песочницы), может не увидеть виртуализированную часть — split-brain: у агента «всё работает», у оператора «файла нет». Для резидентных процессов (hermes gateway, oskard), которые обязан уметь запускать оператор, это недопустимо.

## Решение

Ставить в НЕвиртуализируемые пути: корень профиля (`C:\Users\Ivan\hermes` через `-HermesHome`), Desktop, отдельный диск. Проверка реальности пути: артефакты этой сессии на Desktop (репо OSKAR, vault) доказанно реальны — Иван их видит и редактирует.

## Урок

Любая установка ПО из агентской сессии в AppData — проверять на виртуализацию (смешанные пути в трейсбеках — маркер). Финальная валидация всегда одна: оператор запускает бинарь из собственного терминала.
