# Исходные цели и запросы Ивана — эталон для сверки

Свод всех целей и запросов с первого брифа (2026-08-25) до 2026-10-16. По нему агенты сверяют реализацию, а планировщики — прогресс. Формулировки Ивана — в кавычках.

## 1. Исходный бриф (стратегическая сессия 2026-08-25)

- Переделать с нуля провалившуюся v1 (PF 0.12) как **OSKAR** — мультиагентную трейдинговую систему.
- **Три агента:** один ищет сетапы, второй торгует, третий отслеживает тренды, новости и соцсети.
- Интегрировать **Hermes** (база: резидент + Telegram), **Claudexor** (движок разработки), **Ouroboros** (самоэволюция).
- **Obsidian vault**: документация, логи, идеи, баги, история; через него отслеживать процесс и прогресс.
- **INVEST ZONE** (библиотека книг) — база знаний.
- Стратегия — **IMB/FVG, Smart Money Concepts**. Принцип: «гибкий агент + жесткие правила».
- Сначала стратегическая сессия, потом исполнение.

## 3. План v2 по фазам (утвержден 2026-08-25)

- Фаза 0 — фундамент: конституция (7 статей), контракты, капсы с hash-pin, vault, хуки.
- Фаза 1 — ядро + paper: данные, детекторы SMC, риск-лестница, журнал, исполнение, shadow-прогон.
- Фаза 2 — Hermes + Telegram + Scout/Trader, карточки и кнопки.
- Фаза 3 — **Sentinel** (тренды/новости/соцсети).
- Фаза 4 — learning loop (Analyst, уроки, калибровка).
- Фаза 5 — самоэволюция (Ouroboros/Claudexor) + малый реал по гейту **PF >= 1.3 на 60 сделках**.

Конституция: биржа — единственная правда; LLM выбирает опции меню и не пишет числа; без самоподкрепления; капсы меняются только процедурой ст. 4; дисциплина валидации (ст. 5); Emergency Stop (ст. 6); vault-дисциплина (ст. 7).

## 4. Запросы Ивана по ходу работы

- Коммиты только от его имени, без соавторов; история переписана.
- Vault должен открываться в Obsidian; работать через Obsidian CLI; «обсидиан важен, чтобы отслеживать текущий процесс и прогресс».
- Карточки в Telegram — «только выжимку давать, технику оставить моделям, оставить только самые важные параметры»; кнопки обязаны работать.
- «Кнопка — выставить лимитный ордер по цене, которую нашел, чтобы система одной кнопкой сама все сделала».
- Работа с двух машин (ПК и ноутбук).
- Агент-критик (аналитик предлагает, критик оценивает) — решено: сначала наблюдатель без права вето, судят counterfactual-когорты.
- Рефакторинг и ревью — агентами и через Claudexor/Codex (модель gpt-6-astra); искать уязвимости, баги, улучшения; оба отчитываются с идеями.
- «Все что нашли — исправляй, запускай агентов, пусть исправляют по блокам».

## 5. Запрос 2026-10-16 (текущий)

- Codex через Claudexor проверяет **стратегию**.
- Рой агентов сверяет реализацию с **исходными целями и запросами** (этот документ).
- «Думающий центр»: агенты Claude и Codex общаются и предлагают гипотезы улучшения.
- Два планировщика сверяют прогресс с планом, пишут отчет и план на ближайшее время.
- «Нужно двигать проект, слишком медленно идем, надо ускорять разработку и тестирование, больше реальных кейсов — оттачиваем систему, пока что запускаем **автоматический режим**».
- В боте — переключатель режима «как ползунком»: **автоматический / с подтверждением**.
