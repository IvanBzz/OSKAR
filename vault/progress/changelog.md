## 2026-10-16 — блок H: защита капитала в автомате (R:R по фактической цене, стоп по просадке)

Автомат ставит сделки без нажатия — защита капитала не должна зависеть от того, смотрит ли Иван. Блок закрывает подтвержденные дефекты аудита G1/G5 и пять находок по конституции.
- **R:R по фактической цене (G1)**: исполнитель проверял для «Маркета» только дрейф 0.5% и уменьшал qty, а R:R и стоп не пересчитывал. Пример: вход 100, SL 99, TP 103.2 — R:R 3; по 100.49 — 1.68 < 2.0, но вход проходил. Хуже: кнопка «Маркет» есть и у плана, где Trader выбрал лимитку, — по ней лестница не проверяла R:R вовсе; а лимит-уровень из меню мог быть не той ценой, по которой шла лестница. Теперь шаги лестницы 5–6 (дистанция стопа, геометрия, fee-aware R:R) вынесены в `ladder.check_entry_price` и повторяются исполнителем по цене входа (маркет — текущая, лимит — уровень плана): «R:R по текущей цене 1.68 < 2.0 — вход отменен». Капсы и профиль — через конструктор исполнителя (демон передает реальные).
- **Стоп по просадке (G5)**: `safe_mode.drawdown_pct: 10` был ложной ручкой. `risk/drawdown.py`: пик equity в meta (`equity_peak`), его ведет монитор на полном тике по тому же equity, что у исполнителя (только с биржи — дефолтные $1000 не дают ложной просадки). equity <= пик × 0.9 — защелка `drawdown_halt` в meta + алерт; переживает рестарт, сама не снимается (урок v1). Новые входы — отказ, монитор сопровождает открытые позиции. Снятие — `oskar drawdown-reset` (POST /drawdown/reset): пик := текущий equity с биржи. Защелка видна в `/status` бота и в GET /status.
- **SAFE MODE переживает рестарт**: флаг жил только в памяти — супервизор с авто-рестартом снимал бы «позицию без SL» молча. Взвод (монитор, runner) пишет причину в meta, старт демона восстанавливает с алертом «SAFE MODE восстановлен после рестарта: …», снятие — только `oskar panic-reset` (сначала журнал).
- **Алерты доходят**: монитор слал сырой текст исключения биржи (`&`, `<`, подписанный URL) с parse_mode=HTML и не смотрел ответ. Теперь ошибки — через `short_error`, текст экранируется, `send_text` проверяет ответ Telegram и при ok:false/HTTP-ошибке повторяет без parse_mode.
- **panic/SAFE MODE/просадка перед самой отправкой входа**: исполнитель проверяет флаги (память и meta) в начале и непосредственно перед `place_entry` — вход «в процессе» panic_flatten не видит.
- **Гейт реальных денег — белый список (P0)**: демон стартовал на реальном BingX при любом mode кроме «live» (`real`, `Live`, опечатка) с sandbox:false. Теперь `core/env_gate.paper_gate`: только mode == "paper" и sandbox именно bool True, иначе отказ старта «реальная торговля закрыта гейтом Фазы 5 (60 сделок, PF ≥ 1.3); режим 'X' не разрешен». То же правило — допуск автомата, CLI `sync`, фабрики приватного доступа (sandbox не True — исключение).
- **Предохранитель автомата по коду исхода**: `ExecutionOutcome.kind` (ok / refused_precheck / exchange_rejected / protection_failed / entry_unknown / error). Считаются сбои биржи, таймаут входа и ошибки; «защита не встала» размыкает сразу; отказы предпроверок (цена ушла, лимит, R:R по факту) не считаются.

## 2026-10-16 — режим «автомат / с подтверждением» с переключателем в боте

Иван: «нужно двигать проект... больше реальных кейсов... пока что запускаем автоматический режим. В боте — переключить режим, как ползунком: автоматический / с подтверждением». Это шаг «подтверждение -> автономия» из стартовых решений.
- `core/trading_mode.py`: `TradingMode` (режим в meta журнала, переживает рестарт; по умолчанию — `settings.execution.default_mode`, выставлен `auto`) и `AutoExecutor` (approve -> тот же охраняемый исполнитель, что у кнопок: equity с биржи, лимит позиций, дубль, дрейф цены, pause/safe_mode).
- **Автомат — только paper/VST** (`mode=paper` и `sandbox=true`): вне этой среды режим всегда «с подтверждением», включить автомат нельзя ни из бота, ни через API — реал закрыт гейтом Фазы 5.
- Эскалатор: в автомате план исполняется сразу, карточка приходит уведомлением «🤖 автомат: ...» без кнопок; не исполнилось (проверки/биржа) — approve откатывается и карточка уходит С кнопками, решение за Иваном. Решение пишется в журнал как `executed`.
- **Предохранитель**: 3 отказа биржи подряд -> режим «с подтверждением» + алерт в Telegram.
- **Ползунок**: команда `/mode` в сигнальном боте — сообщение с двумя кнопками (● активная), переключение перерисовывает его; только allowlist-чат и автор. Меню команд бота (`setMyCommands`): /mode /status /panic. `/status` показывает режим. API: `GET /mode`, `POST /mode/{auto|confirm}`.

## 2026-10-15 — блок A: защита прикрепляется к входу (живой 109420 на лимитке BERA)

**Живой случай 2026-10-14 12:03** (первая реальная попытка исполнения на VST): Иван нажал «Лимит 0.2292» по BERA long.
