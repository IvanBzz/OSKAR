# КОНСТИТУЦИЯ OSKAR

> Orchestrated System Kernel for Autonomous Reasoning / Adaptive Risk

## Преамбула

OSKAR — не личность и не становление. OSKAR — инструмент сохранения и приумножения капитала, чья конституция связывает **и систему, и оператора**. Она написана кровью Run #1 версии v1: Profit Factor 0.12, журнал, навравший о PnL в 40 раз, самоусиливающийся SHORT-bias из трех по отдельности разумных компонентов, и пять фиксов, закоммиченных и ни разу не проверенных вживую.

**«OSKAR не вышел на реальные деньги» — легитимный исход-успех, а не провал.** Система, честно доказавшая, что ее edge не существует, выполнила свою работу. Провал — это система, скрывшая этот факт.

## Статья 1 — Единственная правда

Биржа — единственный источник истины о деньгах. Журнал — кеш, и кеш врет (v1: −$329 в журнале против −$7.56 на бирже). Поэтому:

1. Реконсиляция журнал↔биржа выполняется после **первой** закрытой сделки каждого прогона и далее каждые 6 часов.
2. Каждый ордер несет `clientOrderId = OSKAR-{run_id}-{decision_id}` — сопоставление точное, не эвристическое.
3. Read-only `exchange_sync` CLI существует **до** первой сделки.
4. Ни одна оптимизация не имеет права уничтожить возможность восстановить точный промпт, ответ модели и рыночный снепшот, сформировавшие решение. Всё пишется в `analysis_log`.

## Статья 2 — Граница детерминизма

Детерминизм владеет деньгами. LLM владеет суждением.

1. Ни один вывод LLM не достигает биржи иначе как через типизированные контракты (`src/oskar/contracts/`) и полную риск-лестницу.
2. LLM выбирает из **перечисленных опций** (entry/SL/TP кандидаты по id, порожденные детекторами) — свободные числа от модели в исполнение не попадают.
3. Размер позиции, леверидж, лимиты — вычисляет только Python. Модель не знает способа их обойти, потому что канала для этого не существует.
4. Изменение схемы контракта = bump `schema_version` + ревью-коммит.

## Статья 3 — Запрет самоусиления

Урок «14 из 15 SHORT»: риск-блок по направлению портфеля + правило в промпте «align with portfolio» + статистика, порожденная самим блоком, замкнулись в петлю.

1. Вывод компонента не может возвращаться на его же вход как жесткое ограничение.
2. Каждая статистика, попадающая в любой промпт, перечислена в аудируемом манифесте `src/oskar/agents/prompts/STATS_MANIFEST.md` с ответом на вопрос: *«могла ли эта цифра быть порождена фильтрами самой системы?»*
3. Статистика направления портфеля в торговых промптах **запрещена**. Формулировки вида «prefer shorts» / «prefer longs» в промптах запрещены.
4. Статистика производительности показывается только Analyst'у — агенту, который не умеет торговать.
5. Confidence любого агента ограничен `caps.confidence_cap` (75) на уровне схемы, пока калибровочные бины не докажут право на большее (v1: бакет 75+ выигрывал 16.7% — хуже бакета 60-69).

## Статья 4 — Процедура изменения капсов

Ответ на `max_leverage: 20x + force_trade: true`, убившие v1.

1. `config/caps.yaml` закреплен хешем в этой конституции. Рантайм при старте сверяет sha256 (UTF-8, CRLF→LF); несовпадение = `safe_mode` + алерт.
2. Поднятие любого капса требует **всего** нижеперечисленного:
   - ≥ 60 закрытых сделок при текущих капсах с PF ≥ 1.3;
   - Proposal-заметка в `vault/proposals/` с evidence (метрика, N, значения);
   - 48 часов охлаждения между заявкой и применением;
   - двухшаговое подтверждение в Telegram (запрос → код через 10 минут);
   - обновление хеша ниже **тем же коммитом**, с записью поправки в vault.
3. Флаг `force_trade` не существует. Строка запрещена в CI. Эта статья не подлежит упрощению.
4. Понижение капсов (в сторону безопасности) — свободно, обычным коммитом.

## Статья 5 — Дисциплина валидации

v1: пять эмпирически выведенных фиксов закоммичены — и система больше никогда не запускалась. Ценность = 0.

1. Каждый behavior-changing коммит объявляет machine-checkable инвариант в `config/invariants.yaml` (метрика, окно, ожидание) **до** деплоя.
2. Статус `committed_not_live_validated` ставится автоматически (pre-commit hook) и снимается **только** зеленым вердиктом `ops/invariants.py`. Руками — никогда.
3. Не более **2** невалидированных behavior-changing изменений подряд; третье блокируется до валидационного прогона.
4. Красный вердикт инварианта = Telegram-алерт; для изменений риск-класса «detector/risk/execution» — авто-revert.

## Статья 6 — Emergency Stop

1. `panic` (Telegram `/panic`, CLI `oskar panic`, или API) исполняется **немедленно и безусловно**: отмена всех ордеров, safe_mode, останов.
2. Ничто не имеет права задержать, оспорить или «уточнить» panic — включая процедуры этой конституции.
3. Восстановление после panic — только явной командой оператора, никогда автоматически.

## Статья 7 — Vault и память

1. Vault (`vault/`) живет в репозитории; история изменений = git history.
2. Коммит, меняющий `src/`, обязан менять `vault/progress/changelog.md` тем же коммитом (enforced pre-commit hook). Vault, отстающий от кода — ложь в документации (v1: 23 дня отставания).
3. Заметки vault именуются выводом, не темой; знания из книг помечаются `reliability: book_claim` и повышаются до `validated` только Analyst'ом по данным.
