# oskar-approvals

Карточки сетапов шлет сигнальный бот oskard. Кнопки карточки (⚡ Маркет / ⏳ Лимит /
❌ / 💤) обрабатывает сам демон — без Hermes. Этот скилл — для решений Ивана ТЕКСТОМ:

```
python {skill_dir}/scripts/approve.py approve <decision_id>           # тип входа — как выбрал Trader
python {skill_dir}/scripts/approve.py approve <decision_id> market    # вход по рынку сейчас
python {skill_dir}/scripts/approve.py approve <decision_id> limit     # лимитка по уровню плана
python {skill_dir}/scripts/approve.py reject <decision_id>
```

`approve` ИСПОЛНЯЕТ сделку сразу — тот же исполнитель с теми же проверками, что у кнопок
(equity с биржи, лимит позиций, дубль, дрейф цены, R:R по фактической цене, panic / SAFE MODE /
стоп по просадке). Скрипт ждет исход до 90 с. Первая строка вывода — итог:

- `ИСПОЛНЕНО: ...` — вход на бирже (маркет) или лимитка выставлена, SL/TP описаны в строке;
- `НЕ ИСПОЛНЕНО: ... [kind]` — до биржи не дошло (цена ушла, лимит позиций, R:R, флаги
  защиты, отказ биржи до входа). Ордеров нет, карточка жива — Иван может решить снова;
- `ВХОД УШЕЛ НА БИРЖУ, НО: ...` — вход есть, но с проблемой (стоп не встал, таймаут входа).
  Повторно НЕ подтверждать: вторая позиция;
- `ИСХОД НЕИЗВЕСТЕН: ...` — исполнитель упал или демон не ответил вовремя. Повторно НЕ
  подтверждать; посмотреть позиции (`oskarctl.py positions`) и сказать Ивану проверить биржу.

## Правила

1. Пересказывай Ивану ФАКТИЧЕСКИЙ итог из первой строки вывода — кратко, своими словами, с
   символом и причиной. Никогда не говори «Исполняю…» / «взято в работу» до ответа скрипта и
   не обещай исход, которого скрипт не вернул.
2. Тип входа: если Иван не сказал — без третьего аргумента (выбор Trader'а). «По рынку»,
   «сейчас», «маркетом» -> `market`; «лимиткой», «по уровню» -> `limit`.
3. Callback `oskar:approve:<id>` -> `approve.py approve <id>`; `oskar:reject:<id>` -> reject.
   Нажатие кнопки И ЕСТЬ подтверждение — без переспрашиваний.
4. `oskar:snooze:<id>` — ничего не вызывай (карточка живет до TTL), ответь «отложено».
5. HTTP 409 = TTL истек, уже решено или исполнение не подключено (нет ключей биржи) — скажи
   причину из ответа, ничего не повторяй (fail-closed: истекшее не воскрешается).
6. HTTP 423 = система на паузе или в SAFE MODE — approve невозможен, скажи причину.
7. HTTP 404 = неизвестное решение — возьми `pending` через скилл oskar-control.
8. Текстовое одобрение без id: возьми `pending` через скилл oskar-control, найди сетап по
   символу; если совпадений больше одного — уточни у Ивана.
9. НИКОГДА не вызывай approve по собственной инициативе — только явное действие Ивана
   (кнопка или текст).
